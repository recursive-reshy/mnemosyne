## Decisions taken while planning
- **Fixtures are stripped before they are committed (decided with Naresh).** They keep every mail header (Received, ARC, DKIM, `X-EmailOctopus-List-Contact-Id`, `X-HS-Cid`, `Feedback-ID`) and 20–85 long tracking links each, which can identify the subscriber, and the remote is a GitHub repo. 8.2 begins with a tested `stripFixture( message )` in `gmail/scrubMessage.ts` plus a one-shot `scripts/strip-gmail-fixtures.ts`: keep only `Subject`, `From`, `To`, `Date`, `Content-Type`, `MIME-Version` and `List-Unsubscribe` (its URL reduced like the links below), drop `labelIds`, `threadId`, `historyId` and `snippet`, set `id` to the file's name, and in every body rewrite each `http(s)` URL's path and query to `/x` (keeping the host, and keeping a path that contains `unsubscribe`, `preferences` or `subscription` as that word so URL-based footer detection still has something to match). Link text, structure and images (which are then removed by the parser under test) stay. I run it once over the five files and commit them; the `fixture:gmail` script gains the same strip so future fixtures are saved clean.
- **`emailToMarkdown` must keep the whole newsletter, not just Readability's best block.** Newsletters with many sections are the case where Readability-first can drop content. The fixture test compares the output with the plain-text part: every paragraph of 60+ characters in the plain part (before its own footer, not a URL line) must have its first 40 normalized characters in the output, at least 90% of them. I will report the real coverage per fixture at the red step. **If Readability-first fails that on any fixture, I stop and report it before changing the approach**: ADR 0036 chose Readability first, and switching to "whole body" would amend it.
- **Layout tables need no new rule, only a smaller blacklist.** Turndown without a table plugin already treats `table`, `tr` and `td` as blocks and passes their content through; 0.5.0 deliberately adds `table` to its removed list. So `layoutTables: 'unwrap'` is a second Turndown instance built from the same rules minus `table` (built once, as TRD §6.1 says). Tested to prove the content survives and articles are unchanged.
- **`summarizeItems` keeps today's behaviour for refs not in the inbox: 409 `Not in the inbox: …`.** TRD §6.4 says such refs are "ignored, as today", but the code and its tests answer 409. I keep the 409 and note the TRD wording in the checkpoint report (one-line doc fix for Naresh). Per-item failures after that follow TRD §6.4: collected, 422 with the failed titles only if every item failed, otherwise the successful jobs are returned. That is new for feed items too (today the first failure aborts the rest); the affected `feedInbox` tests are listed in the log.
- **New `UnprocessableError` (422)** in `errors.ts` for "every item failed" (TRD §6.4 names the status; there is no error class for it yet).
- **`queueJob` gains `gmail_source_id`** in its `extra` (it currently stores `null`); it sets `gmail_source_id` and `gmail_source_name` on the stored job, like `feed_id` and `feed_name`. This is the "job gets its Gmail source" piece of 8.3.
- **Gmail link needs the account address.** `gmailLink( { email, messageId } )` takes `email: string | null`; with no account (Gmail disconnected, items kept) it falls back to `/u/0/`. The server reads the address from `gmailAccount.findAccount()`.
- **Auto-summarize after a check (the seam left in 6.4):** `runCheck` returns the rows it added. 8.3 makes `checkSource` / `checkDueSources` queue each non-backfilled `inbox` row of an `auto_summarize` newsletter source through `queueNewsletterMessage`, one failure leaving that item in the inbox and logged (as `queueAutomatically` does for feeds). Backfilled rows are never queued (PRD 6.3).
- **Partial failure in the web (8.5):** `SummarizeInboxResponse` is only `{ jobs }`. After the mutation settles and the inbox refetches, the items that were submitted and are still in the inbox are the ones that failed; the snackbar lists their titles ("2 of 5 couldn't be summarized and stay in the inbox: …"). No contract change. The all-failed 422 shows the server's message in the dialog, as errors do now.
- **Naming:** `Inbox` replaces `FeedInbox` (`git mv`, tests move with it); `useInbox`, `useSummarizeInbox`, `useDismissInbox`, `api/inbox.api.ts` replace the feed-item hooks and `api/feedItems.api.ts`, whose `/api/feed-items` shim (ADR 0039) goes away. `inboxKeys.all = [ 'inbox' ]` replaces `feedKeys.inbox`; every place that invalidated the feed inbox (`useFeeds`, `useGmailSources`, the summarize and dismiss hooks) now invalidates it.
- **ADR 0039 ends with 8.4:** the server-local `feedItems.schemas.ts` (and its test) is deleted because the routes use the shared inbox contracts; I set 0039's status to "Superseded by the implementation of 0038 (task 8.4)" in its file and the `docs/README.md` index. No new ADR.

## 8.2 `sources/emailToMarkdown.ts` on the newsletter fixtures (TRD §6.1)
Part 1, fixtures (see decisions): tests for `stripFixture` first (`scrubMessage.test.ts`): headers kept and dropped, ids and snapshot fields dropped or replaced, URLs rewritten in html and plain bodies and in `List-Unsubscribe`, host kept, `unsubscribe`/`preferences`/`subscription` path words kept, query strings gone, mail addresses already scrubbed stay scrubbed, original not mutated, idempotent. Then the script, run once; then the strip added to `save-gmail-fixture.ts`. The script is not unit-tested, only the function. Commit the five stripped files by name.

Part 2, the converter. Tests first (`emailToMarkdown.test.ts`):
- Small hand-written cases, one per step: no HTML → plain text with trimmed lines; `img`/`picture`/`style`/`script`/`head` removed; elements styled `display:none`, `max-height:0`, `mso-hide:all` removed; a first `display:none`/`opacity:0` preheader removed; Readability result used when it reaches `ARTICLE_LIMITS.minExtractedChars`; otherwise the whole cleaned body through `htmlToMarkdown( …, { layoutTables: 'unwrap' } )`; a leading "View in browser / view online / read online" line dropped; a cut from the last block with an unsubscribe / manage preferences / email preferences link, only when it starts in the final third (a mid-article "unsubscribe" mention stays); blank lines collapsed; empty and whitespace-only input → `''`; text-only and html-only inputs; malformed HTML doesn't throw.
- Fixture cases, per fixture: contains the body text (coverage rule from the decisions); no `unsubscribe` footer lines; no `![` images and no tracking pixel URLs; no table syntax (`|` rows, `---|`); doesn't start with a view-in-browser line; length above `minPastedChars`; the title-bearing first section is present. Plus an "every fixture takes either path without error" check.
- Red: module missing, then the first coverage numbers. Green: linkedom + the existing `extractArticle` pattern (`parseHTML`, `Readability` on a clone), `htmlToMarkdown` from 8.1, step 5 trimming as small pure helpers; no new dependency.
- Gate: server.

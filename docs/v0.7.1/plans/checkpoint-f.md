## Findings that shape the plan
- **Base URL check (8.1's first step) passes.** `claude.client.ts:94` and `anthropicModels.client.ts:13` build `new Anthropic( { apiKey, timeout, maxRetries } )`; `agent/claude.py:76` builds `AsyncAnthropic( api_key, http_client, max_retries )` and `main.py:148` passes no `http_client`. No explicit base URL, so `ANTHROPIC_BASE_URL` applies in both. No stop-and-ask.
- `detectSourceType` treats any host outside the video list as an article, so `http://fakes:4000/article` is an article job. I found no private-address guard in `sources/` or `clients/http.client.ts`; the first spec confirms the server can fetch `fakes:4000`.
- Summarizer answers must match `ArticleSummaryResult` (`overview`, `key_points[]`, `quotes[]`, `tags[]`, all strings) as JSON text in a `content` text block, since the server uses `messages.parse` with `output_config.format`. The model list needs `capabilities.structured_outputs.supported`, `capabilities.effort.medium.supported` and `max_tokens` (`listSummaryModels`).
- The linker's submit tool is `submit_suggestions` (`linker/loop.py`, `tools.py`). The agent keeps an anchor only if it appears in the note body, and works out the kind from the vault, so fixture anchors must be phrases from the fixture summary.
- **Gap in TRD §7.3:** `docker-compose.yml` has `env_file: .env` on `mnemosyne`. In the e2e run that would need a `.env` and, if Naresh's exists, load his real secrets. The override sets `env_file: !override []` and passes everything through `environment` (`ANTHROPIC_API_KEY: e2e`, `AGENT_SECRET`, and `VAULT_PATH: /vault` if the Dockerfile doesn't set it; check in 8.2). This stays inside ADR 0053's intent (never touch the real instance); recorded in the log line, no new ADR.
- Compose project `mnemosyne-e2e` gives its own network and volume, so the real `mnemosyne-data` volume is untouched. `agent` has no host port, so only 3101 is published.
- `up --wait` needs healthchecks: `mnemosyne` and `agent` have them; the fakes get one.

## 8.1 `e2e/` package and fakes
Files: `e2e/package.json` (`@mnemosyne/e2e`, private; scripts `test` (a no-op that exits 0, so `pnpm -r test` stays fast), `test:fakes` (`node --test` on the fakes' routing tests, run in the gate), `lint`, `typecheck`, `e2e` → `./run.sh`), `tsconfig.json`, `eslint.config.js` (the house style from `apps/server`), `playwright.config.ts` (baseURL `http://localhost:3101`, Chromium, one worker, `retries: 0`, trace on failure), `fakes/server.mjs`, `fakes/Dockerfile`, `fakes/fixtures/*`; `pnpm-workspace.yaml` adds `e2e`; root `package.json` adds `"e2e": "pnpm --filter @mnemosyne/e2e e2e"`. Dependency: `@playwright/test` pinned to the version `apps/web` uses for `playwright` (1.64.1); `pnpm install` updates the lockfile.
Design of `server.mjs`: a pure `route( method, path, body ) → { status, headers, body }` function exported for tests, plus a thin `node:http` wrapper that runs only when the file is the entry point. Routes per TRD §7.2: `GET /article`, `/article-2`, `/feed.xml` (2 items), `/health`, `GET /v1/models`, `POST /v1/messages` (with `tools` → `tool_use` of `submit_suggestions` with two suggestions; without → summary JSON text), everything else and any unexpected body (not JSON, no `model`, a `tools` list without `submit_suggestions`) → 400 with a message. Every message response carries `id`, `type: message`, `role`, `model`, `stop_reason` (`end_turn`, `tool_use`), `usage`.
Tests first (`fakes/server.test.mjs`, `node:test`, no network): each route's status and content type; `/feed.xml` has 2 items linking to `/article` and `/article-2`; the summary answer has the keys of `ArticleSummaryResult` (a local check, no import from the server); the agent answer has a `submit_suggestions` block and its anchors occur in the summary text; unknown path, bad JSON and a tools list without the submit tool give 400. Red path: file missing → import error; then route by route.
Order: fakes tests red → green → package wiring (lint, typecheck) → commit `feat(8.1): …`. Log line records the base-URL finding.

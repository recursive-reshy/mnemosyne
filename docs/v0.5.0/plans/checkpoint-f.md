## Context
Checkpoint E built the feed endpoints; the shared schemas (`Feed`, `FeedItem`, `PreviewFeedResponse`, `CreateFeedBody`, `UpdateFeedBody`, `SummarizeFeedItemsBody`, …) and `Settings.feed_check_interval_minutes` (`FeedCheckInterval`: 15, 30, 60, 180, 360, 1440) exist. This checkpoint adds the UI: data layer, Settings → Feeds, the add/edit/delete dialogs, and the home-page inbox with the feed chip.

Patterns to follow (all seen in the code):
- `api/*.api.ts`: `request( path, Schema, init )` / `send` from `api/request.ts`, a `jsonInit` helper per file (as in `prompts.api.ts`), parsed with shared schemas; tests stub `fetch`.
- Hooks: TanStack Query, keys in `hooks/queryKeys.ts` (`promptKeys` style), one hook returns the query plus its mutations (`usePromptProfiles`), `renderHookWithClient` in tests.
- Components: folder per component with `index.ts`; `ConfirmDialog` for confirms; dialogs as in `RegenerateDialog` (`useId` title, `Alert` for errors, `SummaryOptions` for profile and model selects); settings fields save at once like `SummarizerDefaults`; `renderWithClient`.
- Files stay under about 150 lines; `role="alert"` errors, `role="status"` progress; MUI `Alert`, `Switch` (labelled), `Menu`.

## 9.1 Data layer (TRD §8.1)
- **New files:** `api/feeds.api.ts` (`listFeeds`, `previewFeed`, `createFeed`, `updateFeed`, `deleteFeed( id, removeItems )`, `checkFeed( id )`, `checkAllFeeds`), `api/feedItems.api.ts` (`listFeedItems`, `summarizeFeedItems`, `dismissFeedItems`), keys `feedKeys = { all: ['feeds'], inbox: ['feed-items'] }` in `queryKeys.ts`, hooks `useFeeds` (query and `create`, `update`, `remove`, `check`, `checkAll` mutations, i.e. "useFeedMutations" folded into one hook as `usePromptProfiles` does; feed changes invalidate feeds and inbox), `useFeedPreview` (a mutation: preview is a one-off lookup, not cached), `useFeedInbox` (query, refetch every 60 s and on window focus), `useSummarizeFeedItems` and `useDismissFeedItems` (summarize invalidates `jobKeys.all` and the inbox; dismiss invalidates the inbox; delete with items also).
- **Tests first** (red before code): `feeds.api.test.ts` and `feedItems.api.test.ts` (each call's URL, method, JSON body, `?remove_items=`, 204 handling, response parsing, error message from `{ error }`, a malformed response), `queryKeys.test.ts` additions, one test file per hook with `api/` mocked (data, error text, invalidation of the right keys, 60-second refetch with fake timers for the inbox, window-focus refetch overrides the app default).
- The inbox hook sets `refetchInterval: 60_000` and `refetchOnWindowFocus: true` on the query (the app default is no refetch on focus).
- Commit `feat(9.1): feeds data layer`.

## Decisions to confirm
1. **`useFeedMutations` is folded into `useFeeds`** (create, update, remove, check, checkAll alongside the list), following `usePromptProfiles`; the TRD names them as separate hooks. Say if you want them split.
2. **9.2 ships without Add/Edit/Delete** (they arrive with their dialogs in 9.3) so no commit has a dead control.
3. **Feed profile select** reuses a small select for profiles only (feeds have no model); `SummaryOptions` is not reused because it always shows a model select.
4. **Dismiss has no confirmation**, as the TRD describes it.
5. **Inbox auto-refresh** is 60 s plus window focus, set on that one query so the app-wide defaults don't change.

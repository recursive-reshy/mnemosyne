# Plan — Checkpoint B (Phases 4–5: server summarizer and API), tasks 4.1–5.4

## Context
Checkpoint A put the contracts and data in place (migration 4, repositories, prompt constants). Checkpoint B makes the server use them: price and model constants, a Claude client that takes a model and guidance and reports usage, a models client and cache, settings and prompt services, summary runs recorded by the worker, `queueJob` options and `regenerateSummary`, then the HTTP API for all of it. Web is untouched (checkpoint C). ADRs 0027–0029 govern; no new ADR expected.

Every task: failing tests first (watch them fail for the right reason) → least code → refactor while green → tick Status + log line → commit (`feat(<id>): …`) → push. After each: `pnpm test`, `pnpm lint`, `pnpm typecheck` in `apps/server` (and `packages/shared` / `apps/web` only if touched). No new dependencies.

- **SDK check (TRD §4.3) passes.** Installed `@anthropic-ai/sdk` is 0.133.0. `client.models.list( { lifecycle: [ 'active' ], limit } )` exists and returns a `PagePromise` that is async-iterable and follows `has_more` itself; `ModelInfo` has `id`, `display_name`, `capabilities: ModelCapabilities | null` (`structured_outputs.supported`, `effort.medium.supported`) and `max_tokens: number | null`. - **`MAX_TOKENS`** (16,000) is needed by both the Claude client and the models client. I'll put it in `summarizer/models.ts` as `SUMMARY_MAX_TOKENS` next to `SHIPPED_DEFAULT_MODEL`, so the clients don't import each other. Small deviation from TRD §4.1's file contents; the value and behaviour don't change.
- **Making `queueJob` async (TRD §4.5, ADR 0028) ripples into existing tests.** `queueJob(` is called 29 times in tests (`jobs.service.test.ts` 20, `jobs.routes.test.ts` 6, `runJob.test.ts`, `summarizeJob.test.ts`, `worker.test.ts` 1 each). Likewise `summarizeJob.test.ts` changes where the client contract changes (4.5): the mock now resolves `{ summary, usage }` and the call is asserted with `{ transcript, model, guidance }`.
- **Prices need outside data (4.1).** TRD says fill `MODEL_PRICES` from Anthropic's pricing page for every model the Models API lists as active, not from memory. I'll fetch the pricing page (WebFetch) and list active models via the Models API with the key in `apps/server/.env` (one read-only GET, key never printed or committed). If either is unavailable (no key, no network), I stop and ask rather than guess prices.
